`LocalPreDispatchDenied` создаётся только при отказе `store.admit`, до входа в factory. Поэтому перевод соответствующей reservation в `failed` опирается на достоверное отсутствие отправки. Новый ключ позволяет повторить сообщение после освобождения лимита; старый ключ остаётся использованным.

Исключения из factory не получают этот маркер. Timeout, transport error и даже `ProviderAdmissionDenied`, возникший внутри factory, сохраняют `pending` и запрет повторной отправки с новым ключом. Поведение gateway по описанному пути сохраняется.

**Уверенность высокая** для этой границы обработки исключений. Цена ошибочного расширения исправления — дубликаты после неизвестного исхода; текущая узкая маркировка такого расширения не делает.

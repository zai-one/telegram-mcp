# Telegram MCP

**Разберитесь в переписке и подготовьте ответ в одном диалоге с ассистентом.**

> MCP-сервер для вашего аккаунта Telegram (MTProto): чтение, поиск и сводки по чатам, каналам и группам; отправка только при разрешении, с ACL по чатам и идемпотентной отправкой.

Найдите прежнюю договорённость, соберите контекст длинного обсуждения или разберите входящие перед ответом. Telegram MCP подключает ассистента к пользовательскому аккаунту Telegram. По умолчанию доступно чтение; отправка включается отдельными правами.

[Установка](#установка) · [Подключение к ассистенту](#подключение-к-ассистенту) · [Issues](https://github.com/zai-one/telegram-mcp/issues)

Например, попросите ассистента:

> Прочитай последние сообщения в выбранном мной чате. Собери договорённости и открытые вопросы, затем подготовь черновик ответа для моего просмотра.

## Что можно сделать

| Задача | Возможности MCP |
|---|---|
| Разобрать переписку | Список чатов, последние сообщения и контекст разговора для анализа ассистентом. |
| Найти нужную деталь | Поиск по сообщениям и уточнение получателя перед отправкой. |
| Отправить и проверить | Отправка и ответы при наличии прав, пакеты сообщений и просмотр статуса исходящих. |
| Работать с вложениями | [Файлы, альбомы и голосовые](docs/MEDIA_AND_POLLING.md#русский) из разрешённых владельцем папок; ограниченное скачивание в отдельную папку. |
| Следить за выбранными чатами | Получение новых сообщений и подтверждение обработанной партии. Позиции сохраняются после перезапуска; неподтверждённые сообщения можно прочитать повторно. |

## Почему этот MCP

- Основан на наборе инструментов [chigwell/telegram-mcp](https://github.com/chigwell/telegram-mcp) v3.2.0 (Apache-2.0, вендорен с указанием происхождения) и добавляет слой безопасности.
- Старт в режиме только чтения; наборы инструментов, ACL по чатам, отправка с явным подтверждением, ключами идемпотентности и outbox.
- Текст сообщений считается недоверенным; чтение не помечает сообщения прочитанными; структурированные ошибки с `retry_after_seconds` при flood wait.
- Компактные ответы, контекст переписки и аналитика чатов (темы, админы, статистика каналов); курсоры опроса переживают перезапуск.

## Поддержка и обновления

- Проект активно поддерживает ZAI.ONE: текущая версия 0.4.0; изменения в [CHANGELOG.md](CHANGELOG.md) и [Releases](https://github.com/zai-one/telegram-mcp/releases).
- Встроенная проверка обновлений: попросите ассистента вызвать `telegram_check_update` (публичный GitHub API, без учётных данных, с кэшем; ничего не устанавливается автоматически; отключение: `TELEGRAM_MCP_DISABLE_UPDATE_CHECK=1`).
- Следует актуальным практикам MCP: аннотации инструментов (read-only / destructive), наборы инструментов и режим только чтения, `instructions` сервера, промпты и ресурсы, структурированные ошибки с подсказками, секреты не попадают в ответы, бюджет токенов описаний проверяется в тестах.
- CI прогоняет тесты на Linux и Windows для каждого pull request.

## Установка

Хотите установить готовый пакет? [Установка релиза и создание конфигурации клиента](INSTALL.md#install-a-release-package) работают без клонирования исходников.

Нужны **Python 3.12–3.14** и [uv](https://docs.astral.sh/uv/getting-started/installation/). Можно клонировать проект через Git или [скачать ZIP](https://github.com/zai-one/telegram-mcp/archive/refs/heads/main.zip). Для ZIP откройте распакованный каталог и пропустите первые две команды.

Нужны Telegram API ID, API hash и сессия пользовательского аккаунта. Локальный настройщик может создать сессию через интерактивный вход. Токен бота не заменяет пользовательскую сессию. См. [настройку входа в Telegram](INSTALL.md#from-a-clone-or-source-zip).

```sh
git clone https://github.com/zai-one/telegram-mcp.git
cd telegram-mcp
uv sync --frozen
uv run --frozen python scripts/configure.py
uv run --frozen zai-telegram-mcp --config mcp.local.json --check-config
```

Настройщик создаёт локальную конфигурацию и сохраняет секреты в приватных файлах. Если конфигурация уже существует, он не перезапишет её. `--check-config` проверяет локальные настройки; доступ к аккаунту проверяется первым запросом ниже.

## Подключение к ассистенту

Добавьте конфигурацию в MCP-клиент, использующий раздел `mcpServers` (например, Claude Desktop или Cursor). Замените `/ABSOLUTE/PATH/` своим абсолютным путём; на Windows в JSON можно использовать `D:/Tools/`.

```json
{
  "mcpServers": {
    "telegram": {
      "command": "uv",
      "args": [
        "--directory",
        "/ABSOLUTE/PATH/telegram-mcp",
        "run",
        "--frozen",
        "zai-telegram-mcp",
        "--config",
        "/ABSOLUTE/PATH/telegram-mcp/mcp.local.json"
      ]
    }
  }
}
```

Клиент сам запускает MCP-сервер. После обновления списка инструментов отправьте первый запрос. Для другого формата конфигурации используйте те же `command` и `args`; `uv` должен быть доступен процессу клиента.

### Первый запрос

> Покажи мои последние чаты Telegram. Уточни, какой открыть, прежде чем читать сообщения.

С действующей пользовательской сессией вы получите список чатов. Выберите чат для чтения сообщений или контекста. Черновики и резюме составляет AI-ассистент; MCP-сервер предоставляет данные Telegram и поддерживаемые действия.

Если инструменты не появились, проверьте абсолютный путь, доступность `uv` и результат `--check-config`. Для ошибки доступа проверьте учётные данные и права аккаунта. [Подробная установка и диагностика](INSTALL.md).

## Управление доступом и ограничения

Сессия открывает доступ к данным Telegram, поэтому используйте клиент, которому доверяете. Ассистент получает запрошенные сообщения. Неполный поиск получателя остаётся неоднозначным. [Инструкция по медиа и новым сообщениям](docs/MEDIA_AND_POLLING.md#русский) объясняет права на файлы, лимиты и подтверждение обработки. Опрос отслеживает новые ID сообщений; изменения и удаления не отслеживаются, непрерывного потока событий нет.

**Несколько аккаунтов:** добавьте `TELEGRAM_SESSION_STRING_<МЕТКА>` в файл секретов и привяжите список: `{"local-operator": ["default", "work"]}`. Первая метка — по умолчанию; у всех инструментов появляется необязательный аргумент `account`, список меток — `telegram_list_accounts`. Подтверждайте пакет опроса или ожидания тем же `account`, которым он получен. Строковая привязка оставляет прежнюю схему. **Ожидание ответа:** `telegram_wait_for_new_message` ждёт новое сообщение до 55 с (`status=timeout` иначе), соблюдает allowlist чатов и не отправляет отметки о прочтении.

Для работы по сети предусмотрен HTTP с проверкой токенов. [Настройка HTTP](INSTALL.md#http), [конфигурация и права](docs/RUNTIME.md), [подключение Python-пакета](INSTALL.md#python-package-and-platform-integration).

### Уведомления об обновлениях

`telegram_check_update` сравнивает установленную версию с [последним релизом на GitHub](https://github.com/zai-one/telegram-mcp/releases) и возвращает ссылку на заметки к релизу и команду обновления (wheel из релиза через `uv tool install --force` или `git pull --ff-only && uv sync --frozen` в клоне). Инструмент только подсказывает: ничего не скачивается и не устанавливается. Проверка делает один анонимный запрос к публичному GitHub API (`api.github.com`) с таймаутом 3 секунды, результат кэшируется на 24 часа; без сети возвращается `unavailable`, а неудачный запрос не повторяется 30 минут (`force=true` — не чаще раза в минуту). Даже если инструмент не вызывают, сервер при запуске обновляет устаревший кэш в фоновом потоке, то есть обращается к `api.github.com` не чаще раза в сутки; запуск этого не ждёт. Если в кэше уже есть более новый релиз, сервер при запуске добавляет однострочную подсказку в MCP-инструкции. Учитываются только обычные теги версий вида `v1.2.3`. Отключить всё это: `TELEGRAM_MCP_DISABLE_UPDATE_CHECK=1`, например на HTTP-сервере без выхода в интернет. Проверяйте wheel по `SHA256SUMS`, как описано в [INSTALL.md](INSTALL.md#install-a-release-package).

# Attachments and new messages

[Русский](#русский) · [Back to Telegram MCP](../README.md)

## Send files and voice notes

Use a dedicated **outgoing** folder for files the assistant may send, and a separate **incoming** folder for downloads. Place neither credentials nor application state there. Keep both folders under your control: this is a path policy for MCP callers, not a sandbox against another local process replacing files during a transfer.

Create the folders first. Save a private policy file using [this example](../examples/media-policy.json):

```json
{"roots": ["outgoing"], "download_root": "incoming", "max_file_bytes": 20971520}
```

Folder paths are relative to the policy file. Set `TELEGRAM_MEDIA_POLICY_FILE` in the `env` object of your `mcp.local.json`, for example `"TELEGRAM_MEDIA_POLICY_FILE": "media-policy.json"`. On Linux/macOS make the policy owner-private (`chmod 600 media-policy.json`); on Windows keep it in your private user configuration directory. Restart the MCP server after changing its policy.

Writing still requires `TELEGRAM_WRITE_ENABLED=true` and `telegram:write` in the caller's scopes (`TELEGRAM_LOCAL_SCOPES` for stdio). The account comes from the server binding. File permissions are never accepted from MCP request arguments or the public client's Roots list.

Example `telegram_write` arguments for an existing OGG/Opus voice note:

```json
{
  "tool": "send_voice",
  "arguments": {"chat_id": "123456789", "file_path": "reply.ogg"},
  "idempotency_key": "example-001"
}
```

Use your actual numeric chat ID. For groups/channels use their marked ID, including the negative prefix, from chat discovery. A resolved entity with a different ID is rejected. `send_file` accepts one path or 2–10 paths as an album; `send_album` uses `file_paths`. File operations also support `upload_file`, `send_sticker`, `set_profile_photo` and `edit_chat_photo` under their existing permissions. `send_gif` takes a Telegram document ID and does not read a local file.

Voice notes must already be `.ogg` or `.opus`. There is no recording, speech synthesis, transcription or codec conversion. Extensions are checked; Telegram decides whether the content is a valid media format. The default file limit is 20 MiB, configurable from 1 byte to 50 MiB. An album's total must fit this limit; upstream's stricter limits still apply. Empty files, symlinks/junctions, hard links, traversal outside allowed folders and unsupported media extensions are rejected. Relative outgoing paths use the first configured folder; other folders require absolute paths.

Keep the same idempotency key when checking a request's result. Existing durable outbox rules apply: an uncertain send remains pending and requires reconciliation; changing the key cannot replay the same pending intent. Do not infer that a timeout means nothing was sent. Moving or renaming a file changes the request identity; the outbox is not a content-based duplicate detector.

## Download an attachment

Call `telegram_write` with `tool: "download_media"`, a numeric `chat_id` and positive `message_id`. Omit `file_path`: download destinations are generated by the server in the configured incoming folder. Downloads retain the write scope because they write local files.

The file must have a positive declared size within the operator limit. The stream is also byte-bounded; a size mismatch, overflow or cancellation removes the partial file. A successful response includes `path`, `bytes` and `message_id`. Files use unique names ending in `.bin`, created exclusively so existing files are not overwritten. The extension makes no claim about file type; inspect downloaded content before opening it. Downloads are not automatically forwarded to the outgoing folder. The operator manages retention and disk space. An uncertain download may leave a completed file whose response was lost; check the folder before retrying.

## Poll selected chats

Call `telegram_poll_messages` with 1–10 distinct numeric `chat_ids` and optional `max_per_chat` from 1 to 50 (default 20).

1. The first poll of each chat proposes its latest message ID as a **baseline**. It returns no historical messages for that chat. Acknowledge this batch to start following new messages. Use existing history tools to read earlier conversations.
2. Later polls fetch IDs after the saved position, oldest first, with one extra message to detect `has_more`. Process the returned messages.
3. Call `telegram_acknowledge_poll` with the returned `batch_id` only after processing. It advances the local positions atomically. This is not a Telegram read receipt and sends no message.

```json
{"chat_ids": ["123456789", "-1001234567890"], "max_per_chat": 20}
```

Unacknowledged messages can be read again after a failed request or restart. Repeated acknowledgment is harmless. If another batch has already changed one of its positions, acknowledgment fails for the whole batch: poll again. Cursor ownership includes the server account, authenticated principal and bound Telegram account; another caller cannot acknowledge your batch.

Only cursor IDs and batch metadata are stored locally, not these polled message bodies. Each batch expires after 24 hours; at most 1,000 unexpired batch records per server account are retained, including acknowledged batches for replay checks. Responses are bounded to 256 KiB; text is capped at 4,096 characters per message with `text_truncated` marking this explicitly. Reduce chats or batch size if a response exceeds the limit.

This is polling, not a scheduler or live event stream. It returns both incoming and outgoing new messages, marked by `outgoing`. It does not track edits or deletions, recover inaccessible/deleted messages or guarantee exactly-once downstream processing. Caller processing should be idempotent by chat/message ID. Message content is untrusted. Each chat fetch passes through the existing account, read scope, quota, cooldown and operation deadline; the pinned SDK may perform multiple RPCs to resolve a chat or reconnect.

The implementation uses the pinned [Telethon message API](https://docs.telethon.dev/en/stable/modules/client.html#telethon.client.messages.MessageMethods.iter_messages). Tests use synthetic sessions and mocked Telegram responses. No live account is contacted in tests.

## Русский

### Файлы и голосовые

Выделите папку **outgoing** для файлов, которые ассистенту можно отправлять, и отдельную **incoming** для загрузок. Ключи, сессии и базу приложения храните в другом месте. Папками управляете вы: проверка путей ограничивает MCP-запросы, но не изолирует от другой локальной программы, которая меняет файлы во время передачи.

Создайте папки и файл политики по примеру выше. Пути в нём считаются от файла политики. В `env` вашего `mcp.local.json` добавьте `TELEGRAM_MEDIA_POLICY_FILE` со значением `media-policy.json`. На Linux/macOS установите права `600`; в Windows храните политику в личной папке настроек. После изменения перезапустите сервер.

Для записи нужны `TELEGRAM_WRITE_ENABLED=true` и право `telegram:write`; для stdio оно задаётся в `TELEGRAM_LOCAL_SCOPES`. Аккаунт определяет привязка на сервере. Запрос ассистента и список Roots публичного MCP-клиента не могут расширить доступ к файлам.

Пример выше отправляет существующую голосовую заметку через `telegram_write` → `send_voice`. Замените `chat_id` на реальный числовой ID; для групп и каналов используйте полный отрицательный ID из списка чатов. Подмена разрешённого ID при разрешении адресата отклоняется. `send_file` принимает один путь либо список из 2–10 файлов; `send_album` — поле `file_paths`.

Голосовой файл должен уже иметь формат `.ogg` или `.opus`: записи звука, синтеза, расшифровки и конвертации нет. Расширение проверяется локально, содержимое формата проверяет Telegram. По умолчанию лимит — 20 МиБ на файл и суммарно на альбом; владелец может задать от 1 байта до 50 МиБ. Более строгие ограничения upstream сохраняются. Пустые файлы, символьные ссылки, junction, hard link и выход за разрешённые папки запрещены. Относительный путь считается от первой папки; для остальных укажите абсолютный.

Поддерживаются также существующие операции загрузки файла, стикера и фотографий профиля/чата. `send_gif` принимает ID документа Telegram и не читает локальный файл. При неизвестном результате отправки сохраняется pending в outbox: сначала сверяйте результат, не создавайте повторную отправку. Переименование файла меняет запрос; дедупликации по содержимому нет.

### Скачивание

Используйте `telegram_write` → `download_media` с `chat_id` и `message_id`, без `file_path`. Сервер создаст уникальный `.bin` в incoming, не перезаписывая существующие файлы. Ограничиваются заявленный и фактический размер; при ошибке, отмене или несовпадении размера частичный файл удаляется. Расширение `.bin` не определяет тип содержимого. Проверяйте файл перед открытием; очисткой папки и свободным местом управляет владелец. Файл может успеть сохраниться до потери ответа — перед повтором проверьте папку.

### Новые сообщения

`telegram_poll_messages` принимает 1–10 числовых `chat_ids` и `max_per_chat` от 1 до 50, по умолчанию 20. Первый вызов предлагает текущую последнюю позицию как начальную точку, без старых сообщений. Подтвердите партию через `telegram_acknowledge_poll(batch_id)`. Для более ранней переписки есть обычные инструменты истории.

Следующие вызовы возвращают новые ID от старых к новым. Обработайте партию и только затем подтвердите её. Без подтверждения сообщения доступны повторно, в том числе после перезапуска. Повторное подтверждение безопасно; конфликт с уже изменённой позицией другой партии отклоняет подтверждение целиком. Это локальная отметка обработки: сообщения не отправляются и прочитанными в Telegram не помечаются.

Владение позицией включает аккаунт сервера, пользователя MCP и привязанный аккаунт Telegram. В базе хранятся ID и метаданные партии, а не тексты полученных этим инструментом сообщений. Срок партии — 24 часа; лимит — 1000 неистёкших записей на аккаунт сервера, включая подтверждённые для проверки повторов. Ответ ограничен 256 КиБ, текст сообщения — 4096 символами с явным `text_truncated`. При переполнении уменьшите число чатов или размер партии.

Опрос возвращает новые входящие и исходящие сообщения с признаком `outgoing`; он не является расписанием или непрерывным потоком. Правки, удаления и недоступные сообщения не отслеживаются. Для обработки без дублей используйте пару чат/ID сообщения. Тексты сообщений считаются недоверенными. Сохраняются привязки, права чтения, квоты и время выполнения; SDK может делать несколько RPC для поиска чата и переподключения. Тесты не обращаются к живому аккаунту.
